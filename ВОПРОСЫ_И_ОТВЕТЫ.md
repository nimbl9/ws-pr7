# Ответы на контрольные вопросы — Практическая работа (Модуль 07)

## 1. Чем аутентификация отличается от авторизации?
- **Аутентификация (Authentication)** — это процедура идентификации субъекта и подтверждения подлинности его личности (ответ на вопрос «Кто вы такой?»). Она проверяет предоставленные учетные данные (логин/пароль, токен, сертификат, биометрию).
- **Авторизация (Authorization)** — это процесс определения прав доступа уже установленного пользователя к запрашиваемому ресурсу или операции (ответ на вопрос «Имеете ли вы право выполнять это действие?»). Авторизация выполняется строго после аутентификации на основе назначенных ролей, разрешений (permissions) или утверждений (claims).

## 2. Для чего используется HTTP-заголовок Authorization?
Заголовок `Authorization` применяется в протоколе HTTP для передачи клиентом учетных сведений серверу. Значение заголовка обычно состоит из названия схемы авторизации (например, `Basic`, `Bearer`, `Digest`) и самих учетных данных или токена. Сервер считывает этот заголовок в фильтрах безопасности и использует его для аутентификации поступившего запроса.

## 3. Почему Base64 не является шифрованием?
Base64 — это метод обратимого **двоично-текстового кодирования**, предназначенный исключительно для надежной передачи бинарных данных через текстовые каналы (ASCII). Он не использует секретный ключ и не обеспечивает конфиденциальность: любой человек или программа могут моментально раскодировать строку Base64 стандартным алгоритмом декодирования. Шифрование же предполагает криптографическое преобразование с применением секретного ключа, без которого расшифровка невозможна.

## 4. Какую роль выполняет интерфейс IPrincipal?
Интерфейс `System.Security.Principal.IPrincipal` представляет контекст безопасности пользователя, от имени которого исполняется код. Он объявляет:
- Свойство `Identity` (типа `IIdentity`), содержащее информацию о личности пользователя (имя, признак аутентификации, тип аутентификации).
- Метод `IsInRole(string role)`, позволяющий проверить, принадлежит ли пользователь к указанной роли безопасности.

## 5. Для чего используются ClaimsIdentity и ClaimsPrincipal?
- **ClaimsIdentity** — реализация `IIdentity`, основанная на утверждениях (Claims). Представляет удостоверение пользователя, состоящее из набора пар «тип-значение» (например: имя, email, ID, отдел, роли).
- **ClaimsPrincipal** — реализация `IPrincipal`, способная содержать одно или несколько удостоверений `ClaimsIdentity`. В ASP.NET Core свойство `HttpContext.User` имеет тип `ClaimsPrincipal`. Эта модель позволяет описывать любые атрибуты пользователя гибко, без жесткой привязки к фиксированной схеме полей.

## 6. Как работает метод IsInRole()?
Метод `IsInRole(string role)` проверяет, сопоставлена ли текущему пользователю указанная роль. В контексте `ClaimsPrincipal` метод просматривает все привязанные утверждения `Claim` с типом `ClaimTypes.Role` (или типом роли, заданным в конфигурации identity). Если среди утверждений находится запись, значение которой совпадает с переданной строкой (с учетом регистра/культуры), метод возвращает `true`, иначе `false`.

## 7. В чём различие между HTTP-кодами 401 и 403?
- **401 Unauthorized** означает отсутствие или недействительность учетных данных аутентификации. Сервер сообщает клиенту: «Вы не подтвердили свою личность, представьтесь (войдите в систему)».
- **403 Forbidden** означает, что пользователь успешно аутентифицирован, сервер понял, кто это, однако прав на выполнение конкретного запроса у данного пользователя недостаточно. Повторная отправка тех же самых учетных данных не изменит результат.

## 8. Для чего используется интерфейс IAuthorizationFilter?
Интерфейс `Microsoft.AspNetCore.Mvc.Filters.IAuthorizationFilter` применяется в конвейере MVC/Web API для создания фильтров авторизации, которые исполняются самыми первыми среди фильтров действий (Action Filters). Метод `OnAuthorization(AuthorizationFilterContext context)` позволяет прервать выполнение запроса (short-circuiting), установив свойство `context.Result` (например, в `UnauthorizedResult` или `StatusCodeResult(403)`), если клиент не прошел аутентификацию или не обладает нужными правами доступа.

## 9. Чем отличается авторизация на уровне контроллера от авторизации на уровне отдельного метода?
- **На уровне контроллера**: атрибут применяется ко всем методам (действиям) данного контроллера по умолчанию. Это гарантирует базовую защиту всего API-ресурса. Исключения настраиваются атрибутом `[AllowAnonymous]`.
- **На уровне метода (action)**: атрибут определяет точечные правила для конкретного HTTP-метода (например, только для удаления `DELETE` или только для определенной роли `Superadmin`), переопределяя или уточняя общую политику контроллера.

## 10. Почему при использовании Basic Authentication необходимо применять HTTPS?
При использовании схемы Basic Authentication учетные данные (логин и пароль) объединяются через двоеточие и кодируются в Base64 без какого-либо криптографического шифрования. В случае передачи по незащищенному протоколу HTTP любой злоумышленник, перехвативший сетевой трафик (через Wi-Fi снифферы, прокси или промежуточные узлы), сможет декодировать пароль за доли секунды. Протокол HTTPS шифрует весь транспортный канал (включая HTTP-заголовки), защищая учетные данные от перехвата и подделки.
